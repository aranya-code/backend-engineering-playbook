# API Gateway + CloudFront

## Overview

Amazon API Gateway can serve APIs directly to clients, but when applications have a global user base, placing **Amazon CloudFront** in front of API Gateway significantly improves performance, security, and scalability.

CloudFront is AWS's global Content Delivery Network (CDN). It caches content at edge locations around the world and routes requests over AWS's optimized global network.

When combined with API Gateway, CloudFront provides:

- Lower latency
- Global edge locations
- Reduced API Gateway load
- Improved security
- Better TLS performance
- DDoS protection
- Edge caching

This architecture is commonly used by large-scale web applications, SaaS platforms, and public APIs.

---

# Why CloudFront?

Without CloudFront:

```text
Client

↓

API Gateway

↓

Backend
```

Every request travels directly to the AWS Region hosting the API.

For users far from the Region:

```text
Higher Latency
```

---

With CloudFront:

```text
Client

↓

Nearest CloudFront Edge

↓

API Gateway

↓

Backend
```

Requests travel through AWS's global backbone network.

# Cache-Control Headers

Applications control caching using HTTP headers.

Example:

```http
Cache-Control: max-age=300
```

CloudFront caches the response for five minutes.

# CloudFront vs API Gateway Cache

| CloudFront Cache | API Gateway Cache |
|------------------|-------------------|
| Edge Locations | Regional Cache |
| Global | Single AWS Region |
| Reduces Internet Latency | Reduces Backend Load |
| CDN | API Cache |

Many production systems use **both** together.

---

# Best Practices

- Place CloudFront in front of public APIs with global users.
- Cache only responses that are safe to cache.
- Use Cache-Control headers to control caching behavior.
- Enable HTTPS for all CloudFront distributions.
- Protect CloudFront with AWS WAF.
- Monitor cache hit ratios to optimize performance.
- Use custom domains with ACM certificates.
- Combine CloudFront caching with API Gateway caching for maximum performance.

# Common Interview Questions

### Why place CloudFront in front of API Gateway?

CloudFront reduces latency by serving requests from edge locations, improves security through AWS WAF and Shield integration, and reduces backend load through caching.

---

### Does CloudFront replace API Gateway?

No.

CloudFront is a Content Delivery Network, while API Gateway provides API management features such as authentication, authorization, request validation, throttling, and monitoring.

---

### Can CloudFront cache API responses?

Yes.

CloudFront can cache cacheable API responses, especially GET requests, based on Cache-Control headers and configured cache policies.

---

### What is the difference between CloudFront Cache and API Gateway Cache?

CloudFront caches content at global edge locations to reduce client latency, whereas API Gateway Cache stores responses within the AWS Region to reduce backend invocations.

---

### Should authentication happen in CloudFront or API Gateway?

Authentication should typically occur in API Gateway. CloudFront focuses on content delivery, caching, and edge security rather than API authorization.

---

# Key Takeaways

- CloudFront improves the global performance of Amazon API Gateway by serving requests through edge locations.
- It reduces latency, improves TLS performance, and decreases backend traffic through edge caching.
- CloudFront integrates with AWS WAF, AWS Shield, and ACM to strengthen security.
- CloudFront and API Gateway caching solve different problems and are often used together in production.
- Combining Route 53, CloudFront, API Gateway, and scalable backend services creates a fast, secure, and globally distributed API architecture.
