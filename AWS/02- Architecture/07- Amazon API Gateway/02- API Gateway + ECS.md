# API Gateway + ECS

## Overview

While **AWS Lambda** is ideal for event-driven and short-lived workloads, many enterprise applications require:

- Long-running processes
- Custom runtimes
- Stateful connections
- Large dependencies
- Docker containers

For these workloads, **Amazon API Gateway** is commonly integrated with **Amazon ECS (Elastic Container Service)**.

In this architecture:

- API Gateway exposes public REST endpoints.
- API Gateway forwards requests to ECS services.
- ECS containers execute the business logic.
- The containers interact with databases, caches, and other backend services.

This is one of the most common architectures for containerized microservices on AWS.

---

# Why API Gateway + ECS?

Without API Gateway:

```text
Client

↓

Application Load Balancer

↓

ECS Service
```

Problems:

- Public ALB exposed
- Authentication handled by application
- No request validation
- Limited API management
- No Usage Plans
- No API Keys

With API Gateway:

```text
Client

↓

API Gateway

↓

VPC Link

↓

Application Load Balancer

↓

ECS Service
```

Benefits:

- Authentication
- Authorization
- API Management
- Throttling
- Monitoring
- Request validation
- Custom domains

# Why Use VPC Link?

API Gateway cannot directly invoke private ECS services.

Instead:

```text
API Gateway

↓

VPC Link

↓

Internal ALB

↓

ECS
```

VPC Link provides secure communication between API Gateway and private resources inside the VPC.

# Lambda vs ECS

| Feature | Lambda | ECS |
|----------|---------|-----|
| Compute Model | Serverless Functions | Containers |
| Infrastructure Management | Fully Managed | ECS Cluster or Fargate |
| Cold Starts | Yes | Minimal |
| Long-Running Tasks | No | Yes |
| Maximum Execution Time | Limited | No practical execution limit |
| Language Support | Supported Runtimes | Any Runtime |
| Docker Support | Container Images Supported | Native |
| Best For | Event-driven APIs | Enterprise Applications |

# Best Practices

- Keep ECS services private behind an internal Application Load Balancer.
- Use VPC Link instead of exposing the ALB publicly.
- Enable JWT or Cognito authentication in API Gateway.
- Validate requests before forwarding them to ECS.
- Configure Auto Scaling based on CPU, memory, or request count.
- Use Fargate for simplified operations unless EC2-specific features are required.
- Enable CloudWatch Logs, Metrics, and AWS X-Ray.
- Deploy ECS services across multiple Availability Zones.
- Keep containers stateless and externalize session storage using Redis or DynamoDB.

# Common Interview Questions

### Why use API Gateway with ECS?

API Gateway provides authentication, authorization, throttling, request validation, monitoring, and API management while ECS focuses on running containerized applications.

---

### Why is VPC Link required?

Because API Gateway cannot directly access private ECS services. VPC Link securely connects API Gateway to internal Application Load Balancers or Network Load Balancers inside a VPC.

---

### Why use ECS instead of Lambda?

ECS is better suited for long-running workloads, custom runtimes, large dependencies, Docker-based applications, and applications that require persistent processes.

---

### Should the ECS Application Load Balancer be public?

No.

A production architecture typically places the ALB in private subnets and exposes only API Gateway to the public internet.

---

### How do API Gateway and ECS scale together?

API Gateway scales automatically. ECS Services use Auto Scaling policies to add or remove tasks based on workload, ensuring the backend can handle increasing traffic.

---

# Key Takeaways

- API Gateway and Amazon ECS together provide a powerful architecture for containerized APIs.
- API Gateway handles API management concerns, while ECS executes application logic inside Docker containers.
- VPC Link securely connects API Gateway to private ECS services through an internal Application Load Balancer.
- ECS is ideal for long-running, container-based workloads that exceed the capabilities of serverless functions.
- Combining API Gateway, ECS, ALB, Auto Scaling, CloudWatch, and AWS X-Ray results in a secure, scalable, and production-ready architecture.
